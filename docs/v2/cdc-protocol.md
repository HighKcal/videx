CDC is the default and only phone transport in this firmware; no WSS listener, TLS certificate, browser origin, pairing token or usb_diag opt-in is required. ## Exact multiplex wire (little endian)

Device→host begins in legacy-compatible mode: unchanged 28-byte CAM2 header then exactly jpeg_size JPEG bytes, maximum 1 MiB. Original CAM2 metadata and JPEG are preserved. No USB2 records are emitted until hello. Python-style CAM2 consumers remain compatible as long as they do not negotiate the extension.

USB2 extension record: 16-byte header, then JSON UTF-8 payload of 1..255 bytes (no NUL/escapes in command fields):

| Offset | Bytes | Meaning |
| --- | --- | --- |
| 0 | 4 | ASCII USB2 |
| 4 | 1 | version = 1 |
| 5 | 1 | kind = 1 host command, 2 device control |
| 6 | 2 | reserved = 0 |
| 8 | 4 | payload byte count (1..255) |
| 12 | 4 | session epoch; zero only on hello |

RX command maximum is 271 bytes total; arbitrary USB packet fragmentation/coalescing is allowed. Partial command timeout: 500 ms. Bad header/JSON/epoch/control queue overflow terminates the negotiated session with a best-effort USB2 disconnected control; stop processing the old session. Never interpret payload bytes as raw mode commands. A single device TX task serializes each whole CAM2+JPEG or USB2 record, never two writers/interleaved bytes. Control FIFO has 16 entries; latest-video has one replaceable slot. Controls go before the next frame (cannot preempt a frame already being written). Whole-record TX deadline 500 ms. On partial TX/timeout, stop that session, do not resume a partial record; host must reset parser/session and reconnect/re-negotiate. Failure notification is best effort when USB itself cannot transmit.

## Negotiation / lifecycle

Host sends USB2 kind=1 epoch=0 JSON exactly {"type":"hello"}. Device replies USB2 kind=2 with new nonzero epoch both in header and JSON: {"type":"connected","epoch":N,"protocol":"cdc2"}. A new hello resets queued controls/frames, pending resolution, gesture state, event counter, and old command dedupe state; desired mode becomes 0 (320x240). An already-started record may finish before connected. Only connected commits the new session to the host; discard prior-generation asynchronous results.

Host sends {"type":"ping"} at least once per second, using the current epoch. Device sends heartbeat every second: {"type":"heartbeat","epoch":N,"camera_online":BOOL,"button_online":BOOL}. Host session lease is 3 seconds without a valid hello/ping/resolution command. Device sends {"type":"disconnected","reason":"heartbeat_timeout"} and cancels pending work on expiry. Host must fail closed/reconnect on missing heartbeat or disconnected; physical USB loss also resets all session/gesture/queue state. No old gesture or queued event is replayed after reconnect. New hello is required after any negotiated session fault. Legacy clients do not have this extension lease.

All device USB2 headers carry the current epoch. Reject stale epochs. Button event_id increments once per generated gesture, starts at 1 each epoch; frontend deduplicates (epoch,event_id), never CAM2 flags in cdc2 mode. Event counter exhaustion terminates the session. BTN2 discontinuity/disconnect cancels held gestures and terminates an active extension session with reason button_disconnected; a fresh hello after recovery cannot convert a reconnect-held button into an action. Button classification uses S3 monotonic elapsed time, debounce 40 ms, long threshold 1 second; short occurs on release, long once while held (release does not additionally emit short). IDF's USB connected flag detects host SOF packets, NOT whether a browser/serial port is open, so heartbeat lease expiry is required even when the cable stays attached.

## Commands / controls

- Mode request: USB2 kind=1, current epoch, JSON exactly {"type":"resolution","request_id":"ASCII_ID","mode":0|1|2}. ID: 1..64 ASCII alphanumeric, underscore or hyphen. Modes: 0=320x240, 1=640x480, 2=1280x1024. One pending request; another different request returns resolution_failed reason busy. Identical last request_id+mode retries do not reapply/repeat ACK; conflicting reuse fails the session. No success ACK on command receipt: resolution_applied follows only a validated JPEG with observed width/height. Five-second timeout; camera absence/disconnect returns resolution_failed. Output is existing {"type":"resolution_applied"|"resolution_failed","request_id":"...","mode":M,"width":W,"height":H,"reason":"observed"|"timeout"|"busy"|"camera_unavailable"|"camera_disconnected"}.
- Independent button controls: {"type":"button_short","epoch":N,"event_id":I} or {"type":"button_long","epoch":N,"event_id":I}. Short=capture, long=cycle selected module on the phone; phone retains explicit user consent gates. Delivered from authenticated CAM BTN2 TCP input, not video/frame flags, so camera-frame absence does not suppress buttons. Never synthesize successful captures or resolution changes from events.
- hello/ping fields are exact, with no extra keys. Resolution uses existing strict JSON command parser. No credential/authenticate JSON over CDC. Duplicate keys, unknown commands, bad epoch/length/version/kind are errors. RX and TX are separate tasks; only TX writes USB bytes.
- Legacy mode command: a single binary byte 0/1/2 or ASCII '0'/'1'/'2', accepted only before extension negotiation. It updates desired CAM mode but sends no USB2 ACK. The legacy host must observe actual CAM2 dimensions. After negotiation, raw bytes are invalid (no competing command owner); use framed mode requests only.

Legacy-only TX stalls drop the unfinished frame and retry a subsequent complete CAM2 record, preserving the prior best-effort streaming/re-sync behavior; a CAM2-only reader is not permanently muted waiting for a hello it never implements. Such a reader must support CAM2 re-synchronization after partial transport loss. Once USB2 was negotiated, TX failure instead mutes the session until hello/physical reconnect; it never silently downgrades the phone to video-flag gestures. A physical USB disconnect clears that negotiation state. Malformed/expired partial commands stop legacy mode writes until a fresh hello or physical reconnect, preventing leftover payload digits from becoming raw mode changes.

## Frontend auto fallback / existing installed boards

Open explicit WebUSB/CDC chooser, reset bounded parser, send hello once; concurrently accept CAM2 frames. Wait up to 1500 ms for a valid USB2 connected. If none, remain legacy CAM2 mode: use raw 0/1/2 and observed-dimension acknowledgement, and use the legacy frame-flag classifier only where the installed board exposes valid raw button samples. The b91f5bf v2 mirror has no USB RX: it may show video but cannot provide resolution RX/reliable independent events until S3 firmware is flashed; do not claim otherwise or silently require WSS. A connected extension chooses the reliable USB2 button path exclusively, ignoring duplicate CAM2 button flags. Never fall back from an established cdc2 fault to frame-flag capture; require a fresh connection/session. An old board can be read without flashing, but new CDC control/independent events require the updated S3 image; board firmware/hardware operation is unverified until an explicit later flash/test.
